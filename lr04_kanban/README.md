## 1. Definition of Workflow

| Колонка | Картка потрапляє сюди, коли | Картка виходить звідси, коли |
| --- | --- | --- |
| Backlog | робота названа на картці з ключем `F-0NN`, але ще не розбита до розміру одного-двох днів | у картці записано, який файл або розділ вважається результатом, і його видно за день-два |
| Ready | у картці названо файл-результат і перевірку завершення (наприклад, «`votes.csv` має 13 рядків», «валідатор без error по файлу») | я відкрив файл-результат і зробив у ньому першу зміну; у цей день пишу дату «У роботі з» |
| In progress | у файлі-результаті є перша зміна, і в колонці менше трьох карток | файл-результат відкривається і читається від початку до кінця, без заглушок і підказок у кутових дужках |
| Review | результат можна відкрити або прочитати: файл збережено, для CSV валідатор пройшов без error | я перечитав результат проти умови ЛР і виправив знайдене; немає відкритих питань до викладача по цій картці |
| Done | результат закомічено в репозиторій або здано; у цей день пишу дату «Завершена» | не виходить: повернення роботи оформлюю новою карткою, а не рухом назад |

Ліміти стоять на самій дошці, у налаштуваннях колонок GitHub Projects
(видно як «0 / 3» і «0 / 2»).

Що ви робите, коли ліміт вичерпано: нову картку не беру, навіть якщо вона
цікавіша; закриваю ту, що вже в роботі, або допомагаю їй пройти Review.

Коли ліміт спрацював: станом на 2026-10-16 ще не спрацював. Рядок допишу того
дня, коли картка вперше чекатиме через вичерпаний ліміт.
